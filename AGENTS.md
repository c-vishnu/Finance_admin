# Prototype Instructions

## AI knowledge transfer

Start with `docs/README.md` for the verified project knowledge base, `docs/WAYVIDA-BOOKS-HANDBOOK.md` for a standalone transfer document, `docs/AI-HANDOFF-PROMPT.md` for a reusable bootstrap prompt, and `docs/project-manifest.json` for the machine-readable inventory. Source and tests remain the authority when prose differs.

### Mandatory feature checkpoint

Every completed feature change must update the knowledge-transfer package before the work is considered complete:

1. Update the relevant modular document in `docs/` with actual behavior, status, dependencies, storage, constraints, and source references.
2. Update `docs/project-manifest.json` when modules, navigation, components, services, persistence keys, tests, dependencies, constraints, or status changed.
3. Update `docs/WAYVIDA-BOOKS-HANDBOOK.md` when essential product, architecture, accounting, security, developer, or operational knowledge changed.
4. Record actual validation and unresolved failures in `docs/TESTING-AND-QA.md`; never claim unexecuted coverage.
5. Refresh `Last verified` in every materially changed knowledge document.
6. Run `npm run docs:check`, relevant tests, and the production build before reporting completion.

### Permanent cross-AI handover rule

This repository must remain transferable to ChatGPT, another Codex account, Gemini, Lovable, Google AI Studio, Antigravity, Claude, or another engineering assistant without access to prior conversation history.

1. Update `docs/TRANSFER-TO-ANOTHER-AI.md` when the current checkpoint, continuation instructions, required files, or known limitations changed.
